## 1. Goal

A marker placed above the door of a room (or on a post at an outdoor site) inside the claim becomes a **building** of the
village. Within about a second its plaque turns **green** when the room meets that building's rules (§3.3: enclosed, minimum
floor, required contents, tier, linked site) or **red** when it does not, and it keeps being re-checked: one building per
second in a round-robin, and at once when the marker is right-clicked. Right-clicking prints a report in chat that lists
every reason, for example *"Needs 1 more chest"*, *"Requires Village tier"* or *"Roof missing at (12, 70, -4)"*. Breaking the
marker removes the building. The three outdoor sites (Mineshaft, Hunting Ground, Training Yard) have their own checks and
link to the nearest parent building.

## 3. Design

### 3.1 Saved data (core + codecs)

```java
public enum BuildingStatus { UNCHECKED, INVALID, VALID }        // core.building; names equal MarkerStatus's (glue maps by name)

public record BuildingRecord(String typeId, HeartLocation marker, BuildingStatus status, @Nullable HeartLocation link) {
    public BuildingRecord(String typeId, HeartLocation marker) { this(typeId, marker, UNCHECKED, null); }   // M1 callers
    public BuildingRecord withStatus(BuildingStatus s); public BuildingRecord withLink(@Nullable HeartLocation l);
    public Optional<BuildingType> type();                            // BuildingType.byId(typeId)
}
```
- `status` is the **last verdict**, persisted so that after a restart M6/M7 see the same valid buildings before the first
  re-check (and buildings in unloaded chunks keep their last verdict, 3.6). `link` is the parent marker for a site (null for
  rooms or an unlinked site). Reasons are **not** saved (recomputed on the next check).
- `VillageState` gains: `withTier(Tier)`, `building(HeartLocation) : Optional<BuildingRecord>`,
  `withBuilding(BuildingRecord)` (insert or replace by `marker`), `withoutBuilding(HeartLocation)`. The compact constructor
  sorts `buildings` by `(dimension, x, y, z)` and throws `IllegalArgumentException` on two records with the same marker.
- Codec `BUILDING` = `type`, `marker`, `status` (`optionalFieldOf("status", UNCHECKED)`, lower-case like `TIER`), `link`
  (`HEART_LOCATION.optionalFieldOf("link")`). M1 saves decode unchanged. In `RAW → VillageState` the codec **drops duplicate
  markers** (first wins) instead of failing, so one bad entry never loses the whole village. `SCHEMA` stays 1 (additive).

### 3.2 Reasons and verdicts (core, `dev.villageheart.core.building`)

```java
public record Reason(Code code, List<Object> args) {            // args: Integer, String, Pos, Tier, BuildingType
    public enum Code { REQUIRES_TIER, OUTSIDE_CLAIM, OTHER_DIMENSION, ROOM, FLOOR_TOO_SMALL, NEEDS_MORE,
                       NEEDS_LINKED_SITE, NO_PARENT, SHAFT_TOO_SHALLOW, INSIDE_HOME_ROOM, NOT_LOADED, NO_VILLAGE }
    public String message();                                     // English, exact (table below)
    public String translationKey();                              // "message.villageheart.reason." + code lower-case
}
public enum Thing { CHEST("chest","chests"), STORAGE_CONTAINER("chest","chests"), BED, LIGHT("light source","light sources"),
    COMPOSTER, CHOPPING_BLOCK, SMOKER, CRAFTING_TABLE, BUILDERS_TABLE, STONECUTTER, FLETCHING_TABLE, GRINDSTONE,
    MARKET_STALL, BLAST_FURNACE, ANVIL, RAIL, NATURAL("grass, leaf or log block","grass, leaf or log blocks"),
    DUMMY("armor stand or target","armor stands or targets");  // one/many forms; default = lower-case words of the name
    public String phrase(int n); }
public record Verdict(BuildingStatus status, List<Reason> reasons, int slots, @Nullable Pos link) {
    public static Verdict deferred(Reason notLoaded);            // status UNCHECKED: "no verdict this time" (3.6)
    public boolean deferred();
}
```

| Code | `message()` (exact) |
|---|---|
| REQUIRES_TIER | `Requires Village tier` / `Requires Town tier` |
| OUTSIDE_CLAIM | `Outside the village: 93 blocks from the Heart (max 80)` (distance rounded down) |
| OTHER_DIMENSION | `Not in the village's dimension` |
| ROOM | M4's `RoomProblem.message()` verbatim, e.g. `Roof missing at (12, 70, -4)`, `Room is shared with the marker at (3, 64, 9)` |
| FLOOR_TOO_SMALL | `Room too small: floor 7 of 9` |
| NEEDS_MORE | `Needs 1 more chest`, `Needs 2 more chests`, `Needs 1 more light source` (`"Needs " + n + " more " + thing.phrase(n)`) |
| NEEDS_LINKED_SITE | `Needs a linked Mineshaft` / `Needs a linked Hunting Ground` |
| NO_PARENT | `No Mine within 48 blocks` / `No Hunting Lodge in the village` / `No Barracks in the village` |
| SHAFT_TOO_SHALLOW | `Shaft too shallow: 9 of 12 blocks deep` |
| INSIDE_HOME_ROOM | `Must be outside House and Farmhouse rooms` |
| NOT_LOADED | `Cannot check now: ` + M4's NOT_LOADED message (deferred only) |
| NO_VILLAGE | `No village yet: place a Village Heart near a bell, then right-click this marker again` |

`STORAGE_CONTAINER` exists so Storage counts chests **and barrels** but still reads *"Needs 1 more chest"* (the roadmap
text). Messages are English in core (like M4); glue sends `Component.translatableWithFallback(translationKey(), message(),
args...)` **[verified `Component.translatableWithFallback(String, String, Object...)`]**, so a later lang file can translate
without code changes and the server needs no lang file now.

### 3.3 Requirement checks (core, pure, L1)

```java
public record RoomFacts(boolean enclosed, List<Reason> structural, int floorArea, Map<String, Integer> counts) {
    public static RoomFacts of(RoomScan scan);   // structural = each RoomProblem as Reason(ROOM, kind, pos, message)
    public int count(String key);                 // counts.getOrDefault(key, 0)
}
public record SiteFacts(int depth, int rails, int lights, int natural, int targets, int armorStands, boolean insideHomeRoom) {}
public record CheckContext(Tier villageTier, @Nullable Reason claimArea,     // OUTSIDE_CLAIM / OTHER_DIMENSION or null
                           @Nullable Pos parentLink, boolean parentExists, // sites: nearest parent in range (3.5)
                           int validLinkedSites) {}                         // Mine/Hunting Lodge: valid sites linked to it
public final class BuildingRules {
    public static Verdict checkRoom(BuildingType t, RoomFacts f, CheckContext c);
    public static Verdict checkSite(BuildingType t, SiteFacts f, CheckContext c);
}
public final class BuildingRequirements { public static Requirements of(BuildingType t); }  // throws for OUTDOOR_SITE
public record Requirements(int minFloor, List<ContentRule> contents, @Nullable String jobKey, SlotRule slots,
                           @Nullable BuildingType requiredSite) {}
public record ContentRule(Thing thing, Set<String> keys, int min) {}   // count = sum of counts over keys
```

**Reason order** (all collected, nothing short-circuits except where said): (1) `claimArea` reason if set (then stop: an
out-of-claim marker is never registered, 3.6); (2) `REQUIRES_TIER` when `t.tier() > villageTier`; (3) if `!enclosed` or
`structural` non-empty: those reasons and stop (contents of a leaking fill are partial, M4 §3.2); (4) `FLOOR_TOO_SMALL`;
(5) each `ContentRule` short of `min`, in table order; (6) `NEEDS_LINKED_SITE` when `requiredSite != null` and
`validLinkedSites == 0`. VALID iff the list is empty. `slots` is computed even when invalid (the report shows it).

| Type | minFloor | Content rules (thing: keys ≥ min) | Slots (M7) |
|---|---|---|---|
| House | 12 | BED: `#bed` ≥1; LIGHT: `#light` ≥1 | homes = `#bed` |
| Storage | 9 | STORAGE_CONTAINER: `#chest` + `minecraft:barrel` ≥2 | 0 |
| Farmhouse | 9 | COMPOSTER: `minecraft:composter` ≥1; CHEST: `#chest` ≥1 | `minecraft:composter` |
| Lumber Camp | 9 | CHOPPING_BLOCK: `villageheart:chopping_block` ≥1; CHEST ≥1 | chopping blocks |
| Kitchen | 9 | SMOKER: `minecraft:smoker` ≥1; CHEST ≥1; CRAFTING_TABLE: `minecraft:crafting_table` ≥1 | smokers |
| Builder's Hut | 9 | BUILDERS_TABLE: `villageheart:builders_table` ≥1; CHEST ≥1 | builder's tables |
| Mine | 9 | STONECUTTER: `minecraft:stonecutter` ≥1; CHEST ≥1; + linked valid Mineshaft | stonecutters |
| Hunting Lodge | 9 | FLETCHING_TABLE: `minecraft:fletching_table` ≥1; CHEST ≥1; + linked valid Hunting Ground | fletching tables |
| Barracks | 16 | GRINDSTONE: `minecraft:grindstone` ≥1; BED: `#bed` ≥ max(1, grindstones); CHEST ≥1 | min(grindstones, beds) |
| Market | 9 | MARKET_STALL: `villageheart:market_stall` ≥1; CHEST ≥1 | market stalls |
| Smithy | 12 | BLAST_FURNACE: `minecraft:blast_furnace` ≥1; ANVIL: `#anvil` ≥1; CHEST ≥1 | blast furnaces |

Barracks' bed rule is the only content rule whose `min` depends on another count ("1 bed per guard slot"); it is a
`ContentRule` with a `minFrom` function (`n -> max(1, grindstones)`). Job-block keys come from `JobBlockType.id()` for the
three new blocks (`"villageheart:" + id`), so a rename breaks a test, not the game silently.

**Sites** (`checkSite`, after (1) and (2) above):

| Site | Checks, in order | Parent (3.5) |
|---|---|---|
| Mineshaft | depth ≥ `Balance.MINESHAFT_MIN_DEPTH` (12) else SHAFT_TOO_SHALLOW; rails ≥ `MINESHAFT_MIN_RAILS` (8) else NEEDS_MORE RAIL; lights ≥ 1 else NEEDS_MORE LIGHT | nearest Mine within `MINESHAFT_LINK_RANGE` (48), else NO_PARENT |
| Hunting Ground | `!insideHomeRoom` else INSIDE_HOME_ROOM; natural ≥ `HUNTING_GROUND_MIN_NATURAL` (40) else NEEDS_MORE NATURAL | nearest Hunting Lodge in the village, else NO_PARENT |
| Training Yard | targets + armorStands ≥ `TRAINING_YARD_MIN_DUMMIES` (2) else NEEDS_MORE DUMMY | nearest Barracks in the village, else NO_PARENT |

A site's parent only has to be **registered** (any status); the parent's own validity needs a **valid** linked site (Mine,
Hunting Lodge) or nothing (Barracks: the Training Yard is optional). So there is no validity cycle.

### 3.4 Site surveys (core scanners over M4's `BlockView`, pure, L1 with `FakeGrid`)

**`ShaftScanner.scan(BlockView v, Pos marker) → ShaftSurvey(depth, deepestY, rails, lights, @Nullable Pos notLoaded)`**.
The Mineshaft marker hangs on a fence post at a player-dug entrance; its own cell is treated OPEN (as M4 does).
Breadth-first fill from the marker cell over OPEN cells (`Dir.values()` order, deterministic), restricted to:
- `y <= marker.y`;
- Chebyshev horizontal distance ≤ `Balance.SHAFT_RADIUS` (16) from the marker;
- **entrance rule:** cells with `y >= marker.y - 1` only within Chebyshev distance 1 of the marker (so surface air does not
  spread: the fill has to go down the hole);
- at most `Balance.SHAFT_MAX_AIR` (4096) cells; reaching it just stops the fill (no error: depth/rails are what was found).
`depth = marker.y - min(y of visited cells)`; `rails` = visited cells with `#rail`; `lights` = `#light` in visited cells
**and** their SOLID neighbours (glowstone in a wall, M4's shell idea); an UNLOADED cell sets `notLoaded` and stops.

**`AreaCounter.count(BlockView v, Pos centre, int radius, String key) → AreaCount(n, @Nullable Pos notLoaded)`**: every
cell with `dx²+dy²+dz² <= radius²` whose `Cell.contents()` contains `key`. Hunting Ground: radius 12, key `#natural`
(~7.2k lookups, once per check). Training Yard: radius 6, key `minecraft:target`.

**Glue (`SiteSurveys`)**: Training Yard armor stands = `level.getEntitiesOfClass(ArmorStand.class, new AABB(centre).inflate(6),
e -> e.distanceToSqr(centre) <= 36)` **[verified `EntityGetter.getEntitiesOfClass(Class, AABB, Predicate)`,
`net.minecraft.world.entity.decoration.ArmorStand`]**, centre = marker block centre. Hunting Ground `insideHomeRoom` = the marker
`Pos` is `occupies(...)`-ed by the latest cached scan of any registered House or Farmhouse (missing cache after a restart →
not inside: lenient, re-evaluated when those rooms are next scanned).

### 3.5 Claim area and links (core, pure)

- `ClaimArea.check(HeartLocation heart, HeartLocation marker, BuildingType t) → @Nullable Reason`: other dimension →
  OTHER_DIMENSION; Euclidean distance between block positions `> maxDistance(t)` → OUTSIDE_CLAIM. `maxDistance` =
  `Balance.CLAIM_RADIUS` (80), except Mineshaft and Hunting Ground = `Balance.OUTDOOR_SITE_RADIUS` (128) (DESIGN §2). Only the
  **marker** position is checked (a room may poke out of the sphere; accepted, see risks).
- `Links.nearest(Pos site, List<Candidate(Pos marker, String dimension)> parents, String dimension, int range) → @Nullable Pos`:
  nearest by squared distance within `range` (`Integer.MAX_VALUE` = "in the village"), same dimension only, ties → the
  smaller `Pos` (x, then y, then z).

### 3.6 Lifecycle: register, unregister, restore, out-of-claim, no claim, unloaded

Glue package `dev.villageheart.building`. All on the server thread.

**Place** (`MarkerBlock.onPlace(state, level, pos, oldState, movedByPiston)` **[verified signature; `LevelChunk.setBlockState`
calls it on every state change unless flag 512, server side only]**): if `oldState.is(this)` → return (a STATUS recolour, or a
facing change: not a new marker). Else, if a claim exists → `BuildingSystem.notePlaced(level, pos)` (adds to a pending set; no
world writes inside `onPlace`). No claim → nothing (the plaque stays grey). This covers player placement, `/setblock`, `/fill`
and structure placement alike, unlike `setPlacedBy` (players only).

**Next tick, pending → registry** (`BuildingSystem.tick`): for each pending pos: chunk loaded and still a `MarkerBlock`? Then
`ClaimArea.check`: a reason → set `STATUS=INVALID` and **do not register** (the Heart never moves, so it can never become valid;
right-click recomputes the reason); otherwise `withBuilding(new BuildingRecord(type, loc))` and queue it at **priority**.

**Remove** (`MarkerBlock.affectNeighborsAfterRemoval(state, level, pos, movedByPiston)` **[verified: called only when the
block changes and the flags include UPDATE_NEIGHBORS, or on a piston move]**): `BuildingSystem.noteRemoved(level, pos)`:
`withoutBuilding(loc)` if registered, drop the caches, and queue the dependents at priority (3.7). This covers breaking by a
player, explosions (`setBlock(..., 3)`), the support wall going (`destroyBlock`) and pistons (`PushReaction.DESTROY`).
**Removals without neighbour updates** are not seen by that hook: `/setblock` places with `2 | 256` **[verified
`SetBlockCommand`]**, so `/setblock ~ ~ ~ air` over a marker skips it. The round-robin therefore also checks the block: a
registered record whose loaded position no longer holds a `MarkerBlock` of its type is unregistered (orphan sweep, like M1's
stale-heart heal). A marker replaced by a different marker type is unregistered (old) and registered (new, via `onPlace`).

**Restore on load.** The registry lives in `VillageState.buildings` (world saved data, M1) and the plaque colour lives in the
chunk's block state, so both survive a restart with no extra work. The transient runtime (scan cache, reasons, queue, cursor)
starts empty; on the first system tick after a server start (or after the claim changes, 3.7) every registered building is
queued at priority so caches refill within `n` ticks for loaded markers.

**No claim.** Markers are inert and grey. Right-click prints NO_VILLAGE. When a Heart is claimed (`VillageHeartBlock.setPlacedBy`
after `CLAIMED`), `MarkerAdoption.adoptLoaded(level, heartPos)` walks the **loaded** chunks within 128 blocks
(`getChunkSource().getChunkNow`), skips sections with `!section.maybeHas(s -> s.getBlock() instanceof MarkerBlock)`
**[verified `LevelChunkSection.maybeHas(Predicate)`, `ChunkAccess.getSections()`]** and adds every marker it finds to pending.
Markers in chunks that are not loaded at claim time are adopted when right-clicked (any right-click of an unregistered marker
with a claim present runs the pending path at once).

**Release** (Heart broken): `VillageClaims.releaseAt` resets `STATUS=UNCHECKED` on every released building whose chunk is
loaded; unloaded ones keep their old colour until right-clicked (then NO_VILLAGE resets them too). Accepted and documented.

**Unloaded chunks.** Nothing loads chunks (M4's `LevelBlockView` uses `getChunkNow`). In the round-robin, a record whose marker
chunk is not loaded is **skipped**: status, link and saved data unchanged, cursor advances. A loaded marker whose scan
reaches an unloaded area (M4 NOT_LOADED, or a site survey's `notLoaded`) gets a **deferred** verdict: block state and saved
status unchanged, the report says *"Cannot check now: Room reaches an unloaded area at …"*. Consumers (M6/M7) use the last
saved status (DESIGN §11: no catch-up while unloaded).

### 3.7 The scheduler

Pure core `RoundRobin<K extends Comparable<K>>` (L1-testable timing), owned by the glue runtime:

```java
public final class RoundRobin<K extends Comparable<K>> {
    public RoundRobin(int intervalTicks, int maxPriorityPerTick);   // Balance.VALIDATION_INTERVAL_TICKS = 20, MAX_PRIORITY_CHECKS_PER_TICK = 1
    public void prioritise(K key);                                  // FIFO, de-duplicated (LinkedHashSet)
    public List<K> tick(SortedSet<K> current);                      // the keys to check this tick, in order
}
```
`tick` increments its own tick counter (independent of game time, so `/time set` and sprinting do not matter). It returns up
to `maxPriorityPerTick` keys from the priority queue that are still in `current` (others are dropped), then, when
`ticks - lastRoundRobin >= intervalTicks`, the next key after the cursor in `current` (wrapping; the cursor is a key, so adding
or removing buildings never skips or repeats one) — unless that key was already returned this tick. So with `n` buildings
each is checked at least every `n × 20` ticks (DESIGN §3.2 "within about `buildings × 1 s`"), and a priority check never
delays the cycle. At most 2 scans per tick.

Glue `BuildingSystem implements VillageSystem`, registered in `VillageHeart.onInitialize` as
`VillageSystems.register("villageheart:buildings", BuildingSystem.INSTANCE)`, so all its work runs inside M2's
`VillageTicker.section()` and shows up in layer 3's `village_ms.*`. The right-click path runs its synchronous check inside its
own `try (var t = VillageTicker.section())`. Runtime state (`BuildingRuntime`: pending set, `RoundRobin<HeartLocation>`
over records sorted by `(dimension, x, y, z)`, latest `RoomScan` per marker, latest `Verdict` per marker) is held per
`MinecraftServer` (a field reset when `server != lastServer`) and is cleared when the claim's identity
`(heart, claimedAtGameTime)` changes, so a release + re-claim or a `VillageTestSupport.reset` never reuses stale caches.

Per tick: (1) process pending placements (3.6); (2) on the first tick for this server/claim, prioritise everything;
(3) for each key from `RoundRobin.tick`: `BuildingValidator.validate(server, record, runtime)`.

**`BuildingValidator.validate`** (one building):
1. Resolve the level from `marker.dimension()`; chunk not loaded (`getChunkSource().getChunkNow(x >> 4, z >> 4) == null`)
   → skip.
2. Block is not a `MarkerBlock` of this type → unregister (orphan) and queue dependents; stop.
3. `claimArea = ClaimArea.check(...)` (normally null: out-of-claim markers are not registered; kept for safety).
4. Survey: ROOM → `RoomScans.scan(level, pos, state.getValue(FACING))`; cache it; **shared rule**: run `SharedRooms.apply` over
   the cached scans of all room buildings (only the enclosed ones matter, M4 3.3); if this building's SHARED state changed, or
   another building now shares its room key, prioritise those others so both turn red (or green again) within a tick or two.
   SITE → `SiteSurveys` (3.4).
5. Survey not loaded → store `Verdict.deferred(...)` for the report; stop (no state change). Steps 5 and 8 go through the pure
   `VerdictPolicy.apply(record, verdict) → (record, changed)`, so the "deferred never changes anything" rule is L1-tested.
6. Context: sites → `parentLink = Links.nearest(...)` over registered records of `t.parent()`; Mine / Hunting Lodge →
   `validLinkedSites` = registered sites of the child type with `status == VALID && link == this marker`.
7. `Verdict v = BuildingRules.check…`; store it.
8. Apply: if the block's `STATUS` differs → `level.setBlock(pos, state.setValue(STATUS, map(v.status())), Block.UPDATE_CLIENTS)`
   (M3's contract; `onPlace` ignores it because `oldState.is(this)`); if `status` or `link` differ from the record →
   `data.update(s -> s.withBuilding(record.withStatus(..).withLink(..)))` (so `setDirty` only on change).
9. Dependents: if a **site**'s status or link changed → prioritise its old and new parent. When a **parent** type is
   registered or removed → prioritise every registered site of its child type (a new Mine can be the link a shaft was missing).

### 3.8 Right-click report

`MarkerBlock.useWithoutItem(state, level, pos, player, hit)` **[verified signature; `ServerPlayerGameMode.useItemOn` calls it when
`useItemOn` returns `TRY_WITH_EMPTY_HAND` (the default) for the main hand and the player is not sneaking with an item]**:
client → `InteractionResult.SUCCESS`; server → `BuildingSystem.useMarker(serverLevel, pos, (ServerPlayer) player)`, return
`SUCCESS`. A right-click while holding a marker therefore reports instead of placing a second marker (sneak to place).

`useMarker`: no claim → set `STATUS=UNCHECKED` if needed, send NO_VILLAGE. Unregistered → run the pending path now (which may
register it or set it INVALID with the claim-area reason). Registered → `validate` **now** (synchronous; DESIGN "immediately
when the marker is used"). Then send `MarkerReport.lines(type, pos, verdict, record)` with `player.sendSystemMessage(Component)`
**[verified]** (chat, not the action bar), one message per line:

```
Storage at (12, 64, -3): invalid          (red header; "valid" green, "not checked yet" / "cannot check now" grey)
 - Needs 1 more chest                     (one line per reason, white)
 - Requires Village tier
Worker slots: 1   |   Homes: 2   |   Containers: 2          (valid rooms: the slot line for that type)
Linked to Mine at (40, 70, 12)            (sites with a link)
```
Header key `message.villageheart.marker.<valid|invalid|unchecked|deferred>` with fallback `"%s at %s: valid"` etc. and args
(`displayName()`, `Pos.toString()`); detail keys `message.villageheart.marker.slots|homes|containers|linked`. Everything uses
`translatableWithFallback`, so en_us.json needs no new keys (LangCoverageTest unchanged; optional entries may be added later).
The latest verdict is also exposed as `Buildings.report(server, loc) : Optional<Verdict>` for M8's Buildings tab.

### 3.9 API for later milestones (glue facade `dev.villageheart.building.Buildings`)
