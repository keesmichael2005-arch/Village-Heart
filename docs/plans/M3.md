## 1. Goal

The player can craft a **Blank Marker** (8 planks around an item frame) and turn it into one of **14 building markers**
(11 buildings + 3 outdoor sites) by surrounding it with that building's ring ingredients. Each marker is a small plaque with
its own readable icon that hangs on the side of a wall (or a fence post), faces outwards, and pops off as an item when its
wall is removed. Three new craftable job blocks exist: the **Chopping Block**, the **Builder's Table** and the **Market Stall**.
Nothing validates yet (M5); every marker shows its grey "not checked" plaque.

## 3. Design

### 3.1 Data model in `core` (pure Java): `dev.villageheart.core.building`

One enum is the single source for every building/site: registration, assets, recipes, lang checks, and later M4/M5
validation, M7 jobs and the M8 Buildings tab all read it.

```java
public enum BuildingKind { ROOM, OUTDOOR_SITE }

/** 3×3 ring around the Blank Marker. Ingredient strings use the vanilla recipe syntax: "minecraft:chest" or "#minecraft:planks". */
public record Ring(String corner, String top, String left, String right, String bottom) {
    public static Ring uniform(String corner, String edge);          // all four edges = edge
    public static Ring withTool(String corner, String tool, String edge); // tool on the TOP edge (directly above the marker), edge on the other three
    // compact ctor: every ingredient matches Ingredients.VALID (regex  #?[a-z0-9_.-]+:[a-z0-9_/.-]+ ) else IAE
    public ShapedSpec recipe(String resultId, int count);            // pattern + key, see below
}

public enum BuildingType {
    //            id               display name       tier     kind          ring                                                               parent (sites)
    HOUSE        ("house",         "House",          HAMLET,  ROOM,         Ring.uniform("#minecraft:planks",  "minecraft:white_wool"), null),
    STORAGE      ("storage",       "Storage",        HAMLET,  ROOM,         Ring.uniform("#minecraft:planks",  "minecraft:chest"), null),
    FARMHOUSE    ("farmhouse",     "Farmhouse",      HAMLET,  ROOM,         Ring.uniform("minecraft:dirt",     "minecraft:wheat"), null),
    LUMBER_CAMP  ("lumber_camp",   "Lumber Camp",    HAMLET,  ROOM,         Ring.withTool("#minecraft:logs",   "minecraft:stone_axe", "minecraft:stick"), null),
    KITCHEN      ("kitchen",       "Kitchen",        HAMLET,  ROOM,         Ring.uniform("minecraft:cobblestone", "minecraft:coal"), null),
    BUILDERS_HUT ("builders_hut",  "Builder's Hut",  VILLAGE, ROOM,         Ring.uniform("minecraft:brick",    "minecraft:ladder"), null),
    MINE         ("mine",          "Mine",           VILLAGE, ROOM,         Ring.withTool("minecraft:cobblestone", "minecraft:stone_pickaxe", "minecraft:rail"), null),
    HUNTING_LODGE("hunting_lodge", "Hunting Lodge",  VILLAGE, ROOM,         Ring.uniform("minecraft:leather",  "minecraft:arrow"), null),
    BARRACKS     ("barracks",      "Barracks",       VILLAGE, ROOM,         Ring.uniform("minecraft:cobblestone", "minecraft:iron_ingot"), null),
    MARKET       ("market",        "Market",         VILLAGE, ROOM,         Ring.uniform("minecraft:white_wool", "minecraft:emerald"), null),
    SMITHY       ("smithy",        "Smithy",         TOWN,    ROOM,         Ring.uniform("minecraft:iron_ingot", "minecraft:smooth_stone"), null),
    MINESHAFT    ("mineshaft",     "Mineshaft",      VILLAGE, OUTDOOR_SITE, Ring.uniform("minecraft:rail",     "minecraft:torch"), "mine"),
    HUNTING_GROUND("hunting_ground","Hunting Ground", VILLAGE, OUTDOOR_SITE, Ring.uniform("minecraft:stick",    "minecraft:feather"), "hunting_lodge"),
    TRAINING_YARD("training_yard", "Training Yard",  VILLAGE, OUTDOOR_SITE, Ring.uniform("minecraft:hay_block", "minecraft:wooden_sword"), "barracks");

    public String id();                 // snake_case, stable: part of save data (BuildingRecord.typeId) and of every asset path
    public String displayName();
    public Tier tier();
    public BuildingKind kind();
    public Ring ring();
    public Optional<BuildingType> parent();   // resolved lazily from the parent id (enum constants cannot forward-reference)
    public String markerId();           // id + "_marker", e.g. "lumber_camp_marker": block id, item id, recipe id, texture base name
    public static Optional<BuildingType> byId(String id);
}

public enum JobBlockType {
    CHOPPING_BLOCK("chopping_block", "Chopping Block",  BuildingType.LUMBER_CAMP),
    BUILDERS_TABLE("builders_table", "Builder's Table", BuildingType.BUILDERS_HUT),
    MARKET_STALL  ("market_stall",   "Market Stall",    BuildingType.MARKET);
    public String id(); public String displayName(); public BuildingType building();
    public ShapedSpec recipe();          // see 3.4
}

/** A shaped crafting recipe as data; renders to the 1.21.11 JSON format (used by the asset generator, checked by L1 and L2). */
public record ShapedSpec(List<String> pattern, Map<Character, String> key, String resultId, int count) {
    // compact ctor: 1..3 rows, equal widths ≤ 3, every non-space char has a key entry and every key is used, count ≥ 1
    public Map<String, Object> toJson();  // {"type":"minecraft:crafting_shaped","category":"misc","key":{...},"pattern":[...],"result":{"count":n,"id":...}}
}
```

Decisions pinned here (tests hold them):
- **Ingredient choices** where §3.3 is ambiguous: "planks" = `#minecraft:planks`, "log" = `#minecraft:logs` (vanilla's
  campfire uses the same tags), "bricks" = the `minecraft:brick` **item** (like "iron ingot", the crafting material, not the
  block), "coal" = `minecraft:coal` (exactly as written; not `#minecraft:coals`), "white wool" = `minecraft:white_wool`, "hay bale"
  = `minecraft:hay_block`. Everything else is the exact item. "wooden sword" means all four edges (4 wooden swords), as written.
- **Tool rings** (Lumber Camp, Mine): the tool sits on the **top edge**, the other three edges are sticks/rails. Shaped
  recipes match the mirror image too (`ShapedRecipePattern.matches(input, true)` **[verified]**), which does not matter
  here because every ring is left-right symmetric; a tool on the bottom or side edge does **not** match (documented in the
  recipe book view, tested as a negative).
- **Outdoor site tiers** follow their parent building (all three are Village). `parent` is used by M5's linking.
- `Balance.BLANK_MARKER_YIELD = 1` *(tunable)*: the generator writes it into `blank_marker.json`; the L2 test reads it.
- Pattern for a ring: `["CTC", "L#R", "CBC"]` with `#` = `villageheart:blank_marker`; identical edge ingredients collapse to
  one key letter, so a uniform ring is `["CEC","E#E","CEC"]` with keys `C`, `E`, `#`.

#### MarkerBlock (wall-mounted, like `WallSignBlock`)

```java
public static final EnumProperty<MarkerStatus> STATUS = EnumProperty.create("status", MarkerStatus.class);   // [verified signature]
public static final MapCodec<MarkerBlock> CODEC = RecordCodecBuilder.mapCodec(i -> i.group(
        BUILDING_TYPE_CODEC.fieldOf("building").forGetter(b -> b.type), propertiesCodec()).apply(i, MarkerBlock::new));
private static final Map<Direction, VoxelShape> SHAPES = Shapes.rotateHorizontal(Block.boxZ(14, 1, 15, 15, 16));
        // [verified] boxZ(width, minY, maxY, minZ, maxZ) = box(1,1,15, 15,15,16): a 14×14×1 plaque on the SOUTH side for FACING=NORTH;
        // Shapes.rotateHorizontal maps NORTH→identity, EAST/SOUTH/WEST rotated (exactly how WallSignBlock builds its shapes)
```
- **Facing semantics (M4/M5 rely on this):** `FACING` is the direction the plaque's front faces, i.e. **out of the wall**.
  The supporting wall block is `pos.relative(FACING.getOpposite())`; the building's door/inside is behind that wall.
- `createBlockStateDefinition`: `FACING, STATUS`. Default state: `FACING=NORTH, STATUS=UNCHECKED`. 12 states per marker.
  M5 changes only `STATUS` with `Block.UPDATE_CLIENTS` (2) so a recolour causes no neighbour updates.
- `canSurvive(BlockState, LevelReader, BlockPos)` **[verified 1.21.11 signature]**:
  `level.getBlockState(pos.relative(state.getValue(FACING).getOpposite())).isSolid()`, exactly `WallSignBlock`'s rule.
  `isSolid()` is the legacy-solid flag **[verified `calculateSolid`]**: true when the collision box is ≥ 0.729 in size or ≥ 1 tall.
  So walls, glass, glass panes, fences (collision 1.5 tall), fence gates and leaves support a marker; air, torches, flowers,
  carpets, slabs-on-their-own-side (bottom slab: 0.5 tall, size 0.83 → **solid**, accepted) and other markers (noCollision) do not.
  Outdoor-site markers therefore hang on the side of a fence post, as §3.3 asks.
- `getStateForPlacement(BlockPlaceContext)`: (1) if `ctx.getClickedFace()` is horizontal, try `FACING = clickedFace`;
  (2) otherwise (top/bottom face clicked) iterate `ctx.getNearestLookingDirections()` **[verified]** and for each horizontal
  `d` try `FACING = d.getOpposite()` (the wall-sign fallback); return the first state that `canSurvive`, else `null`
  (vanilla `BlockItem.place` then fails without consuming the item). Always `STATUS=UNCHECKED`.
- `updateShape(BlockState, LevelReader, ScheduledTickAccess, BlockPos, Direction, BlockPos, BlockState, RandomSource)`
  **[verified 1.21.2+ 8-arg signature]**: `direction.getOpposite() == state.getValue(FACING) && !state.canSurvive(level, pos)
  ? Blocks.AIR.defaultBlockState() : super.updateShape(...)`. Returning air makes `Block.updateOrDestroy` call
  `level.destroyBlock(pos, true, null, limit)` **[verified]**, which runs the loot table: the marker **drops as an item**
  whenever its support is removed (player break, `/setblock`, `/fill`, explosion, piston) with neighbour shape updates.
- `getShape(...)` returns `SHAPES.get(FACING)`. `codec()` returns `CODEC`. `rotate`/`mirror` come from `HorizontalDirectionalBlock` and keep STATUS.
- Properties: `.mapColor(MapColor.WOOD).noCollision().noOcclusion().strength(1.0f).sound(SoundType.WOOD).ignitedByLava().pushReaction(PushReaction.DESTROY)`.
  No `forceSolidOn` (a marker must not support another marker). No waterlogging in M3.
- `BUILDING_TYPE_CODEC = Codec.STRING.comapFlatMap(id -> BuildingType.byId(id).map(DataResult::success).orElseGet(() -> DataResult.error(() -> "unknown building " + id)), BuildingType::id)`.
- No block entity, no `useWithoutItem` (right-click reasons are M5), no building registration on place (M5).

#### JobBlock

- `FACING` towards the placer: `defaultBlockState().setValue(FACING, ctx.getHorizontalDirection().getOpposite())` (furnace style).
- Shapes: Chopping Block `Block.box(1, 0, 1, 15, 12, 15)` (a stump); Builder's Table and Market Stall full cubes.
- Properties: `.mapColor(MapColor.WOOD).strength(2.0f).sound(SoundType.WOOD).ignitedByLava()`, plus `.noOcclusion()` for the Chopping Block.
- `CODEC` like the marker's, with a `JobBlockType` string codec.
- They are **plain blocks in M3**: no POI type, no profession, no menu. M7 registers them as job-block POIs; M20 adds the
  Builder's Table screen; M22 the Market Stall behaviour.

### 3.3 Assets: generated from the enums, checked by a golden test

**Decision: a small pure-Java generator in the test source set, not Fabric datagen and not hand-written files.**

| Option | For | Against |
|---|---|---|
| Hand-written JSON | Nothing new to build | ~150 files (14 markers × blockstate + 3 models + item def + item model + loot + recipe + advancement, …); every new type in a later milestone means 10 edits; easy to drift from the enum |
| Fabric datagen (`fabricApi.configureDataGeneration`, `FabricRecipeProvider`, `FabricModelProvider`) | Vanilla codecs guarantee format | Boots Minecraft (`runDatagen`, ~1 min) in a build that already juggles `splitEnvironmentSourceSets` + `configureTests` + a custom run; the 1.21.2+ `RecipeProvider.Runner` / model-generator APIs need their own spike; textures still need a separate tool; stale output is only caught if verify runs datagen and diffs |
| **Java generator over the core enums** (chosen) | Reads `BuildingType`/`JobBlockType` directly (single source); makes JSON *and* PNG textures (`javax.imageio`, headless) in one place; runs in ~1 s; an **L1 golden test** fails if a committed file differs from what the generator produces, so drift is impossible to miss | Format mistakes are not caught at L1, so L2 must load every recipe/loot table/advancement and L4 must check models (both planned below) |

Layout:
- `src/test/java/dev/villageheart/tools/AssetGenerator.java`: `static Map<String, byte[]> generate()` (relative path under
  `src/main/resources` → bytes) and `main(String[] args)` that writes them under `args[0]` and writes a preview sheet (below).
- `src/test/java/dev/villageheart/tools/MarkerArt.java`: palette + per-type glyphs as ASCII pixel art + `BufferedImage render(BuildingType, MarkerStatus-name)`; `JobBlockArt.java` likewise.
- `build.gradle`: `tasks.register('genAssets', JavaExec) { classpath = sourceSets.test.runtimeClasspath; mainClass = 'dev.villageheart.tools.AssetGenerator'; args file('src/main/resources').absolutePath, file('build/asset-preview').absolutePath; systemProperty 'java.awt.headless', 'true' }`
  and `test { systemProperty 'villageheart.resourcesDir', file('src/main/resources').absolutePath }` for the orphan check.
- The generated files are **committed**. Workflow: change an enum or art → `./gradlew --no-daemon genAssets` → commit.
- JSON is written with `core.sim.Json.write(map, true)` from `LinkedHashMap`s, so output is byte-stable.
- **Lang stays hand-written** (`en_us.json` also has the claim messages). An L1 test checks every expected key/value instead.

### 3.4 Recipes

1.21.11 shaped format **[verified against vanilla `chest.json`, `campfire.json`, `item_frame.json`]**: keys map to a string
(`"minecraft:x"` or `"#minecraft:tag"`), result is `{"count": n, "id": "..."}`, `"category": "misc"`.

| Result | Pattern | Keys |
|---|---|---|
| `blank_marker` ×`BLANK_MARKER_YIELD` | `PPP / PFP / PPP` | P `#minecraft:planks`, F `minecraft:item_frame` |
| `<type>_marker` | from `Ring.recipe` (3.1) | ring ingredients + `#` `villageheart:blank_marker` |
| `chopping_block` | `A / L` (1×2, any column) | A `#minecraft:axes`, L `#minecraft:logs` |
| `builders_table` | ` P  / BCB` | P `minecraft:paper`, B `minecraft:brick`, C `minecraft:crafting_table` |
| `market_stall` | `WWW / PEP` | W `#minecraft:wool`, P `#minecraft:planks`, E `minecraft:emerald` (vanilla beds are `WWW/PPP`; the emerald keeps it distinct) |

Recipe tests fetch through the **server** recipe manager **[verified]**: `ServerLevel.recipeAccess()` returns the
`RecipeManager`; `getRecipeFor(RecipeType.CRAFTING, CraftingInput.of(3, 3, stacks), level)` returns
`Optional<RecipeHolder<CraftingRecipe>>` (first match); `holder.id()` is a `ResourceKey<Recipe<?>>`
(`.identifier()` for the id); `holder.value().assemble(input, level.registryAccess())` gives the result stack;
`recipeAccess().getRecipes()` lists all holders (used to prove each grid matches **exactly one** recipe).
`CraftingInput.of` trims empty rows/columns **[verified `ofPositioned`]**, so the 1×2 Chopping Block grid can be given in any column.

   (Placement works from here on, but the blocks render as missing models until step 3/4; that is expected.)

## 6. Risks and unknowns

1. **Readability of 14 icons at 16×16 (top risk).** The L4 criterion is judged by eye. Mitigation: big contrasting glyphs on
   distinct backgrounds, the ×8 preview sheet before any client run, the pixel-distance test, and a camera at ~4.6 blocks so a
   texel is ~7 screen pixels. Budget one or two art iterations in step 4/6.
2. **Generated assets drift or are edited by hand.** The golden test (T-L1-8) makes it a red L1. The generator lives in the test
   source set, so it never ships in the mod jar.
3. **Format errors invisible at L1.** Vanilla logs and skips a bad recipe/loot/advancement file. T-L2-4/-5/-11 prove each one
   loaded; T-L4-1/-3 prove each model and texture resolved.
4. **Block models cannot use item textures in 1.21.11** (verified: separate `items` atlas). Covered by design and by T-L4-3.
5. **GameTest batch interference.** Marker tests share one environment and only remove their own players; drop tests assert
   `block_drops` is on.
6. **Tool on the top edge only.** Players may expect the axe/pickaxe in any edge. Accepted for v1 (recipe book shows the
   layout); four rotated recipes are a cheap later change if playtesting asks for it.
7. **`isSolid()` is a legacy flag** that Mojang may change; it is what wall signs use in 1.21.11, so markers behave like signs.
