## 1. Goal

The first Heart a player places next to a bell claims that village for the whole world. The
claim survives a save and reload. A second Heart anywhere in the world is refused with a message
and is not placed. Only the Owner can break the claimed Heart. Breaking it releases the village
and drops the treasury as emeralds, and after that a new claim can be made anywhere.

## 3. Design

### 3.1 Behaviour decisions (these are the rules; tests pin them)

1. **Claim at placement.** `getStateForPlacement` runs the claim *check*, and `setPlacedBy` *commits*
   the claim. Both run on the server thread in the same `BlockItem.place` call, so nothing can
   change in between.
2. **Refused placements do not place the block.** On the server, `getStateForPlacement` returns
   `null` for `NO_BELL_NEARBY` and `ALREADY_HAVE_VILLAGE` (and when there is no player). Vanilla
   `BlockItem.place` then returns `FAIL` and does not consume the item. The placer gets an
   action-bar message. On the client, `getStateForPlacement` always returns the default state (the
   client cannot know the claim), and the server's block-update packet (which vanilla
   `handleUseItemOn` always sends) removes the predicted ghost block. Vanilla does **not** resync
   the client's predicted item decrement, so after a refusal the server calls
   `serverPlayer.containerMenu.sendAllDataToRemote()` **[verified exists]**.
3. **One claim per server** (the "world"). It is stored in the **overworld's** data storage
   (`server.overworld().getDataStorage()`) whatever dimension the Heart is in. The Heart's
   dimension is stored with its position.
4. **Owner only.** Breaking the *claimed* Heart (the one whose dimension and position equal the
   stored claim) is allowed only for the owner UUID. This holds in creative too. No op bypass in M1
   (see Risks). A Heart block that is *not* the claimed one (e.g. made with `/setblock` or a
   GameTest `setBlock`) is inert: anyone can break it and nothing is released.
5. **Release on any removal of the claimed Heart.** The owner's break, `/setblock`, `/fill` and
   anything else that removes the block with neighbour updates go through
   `affectNeighborsAfterRemoval`, which releases the claim and drops the treasury. The release is
   idempotent and only acts when the position matches the claim.
6. **Stale-claim self-heal.** Some removals skip `affectNeighborsAfterRemoval` (setBlock flags
   without `UPDATE_NEIGHBORS`, structure tools, external editors). When a claim is evaluated and the
   stored Heart's chunk **is loaded** (`level.isLoaded(pos)`) but the block there is not a Village
   Heart, the stale claim is released first (the treasury drops at that position), and then the new
   claim is evaluated normally. An unloaded chunk is never loaded for this check and never counts
   as stale.
7. **Hard to destroy by other means.** `PushReaction.BLOCK` stops pistons. Block tags
   `minecraft:wither_immune` and `minecraft:dragon_immune` stop withers and the dragon. Blast
   resistance 1200 already stops TNT and creepers.
8. **Fresh village on re-claim.** After a release, the next claim starts from defaults: treasury 0,
   tier HAMLET, no ranks, empty registries.
9. **Messages** (action bar, `displayClientMessage(..., true)`):
   - `message.villageheart.claim.claimed` (existing)
   - `message.villageheart.claim.no_bell_nearby` (existing)
   - `message.villageheart.claim.already_have_village` (existing, shown to the owner): "You already have a village in this world."
   - **new** `message.villageheart.claim.already_claimed_other`: "This world's village already belongs to %s." (shown to anyone else, with the owner's name)
   - **new** `message.villageheart.heart.not_owner`: "Only %s can break the Village Heart."
   - **new** `message.villageheart.heart.released`: "Your village has been released." (sent to the owner if online, as a chat message)

### 3.2 Core (pure Java, `dev.villageheart.core`, no `net.minecraft` and no DFU imports)

All new types are immutable records/enums, apart from `WorldClaim`.

```java
public record HeartLocation(String dimension, int x, int y, int z) {}      // dimension = "minecraft:overworld" etc., non-null, non-blank

public enum Rank { OWNER, STEWARD, RESIDENT, VISITOR;                       // declared from most to least power
    public boolean atLeast(Rank other) { return ordinal() <= other.ordinal(); } }

public enum Tier { HAMLET, VILLAGE, TOWN }

public record BuildingRecord(String typeId, HeartLocation marker) {}       // placeholder; M5 extends (fields added later as optional)
public record WorkerRecord(UUID villager, String jobId) {}                 // placeholder; M7 extends

public record VillageState(HeartLocation heart, UUID owner, String ownerName, long claimedAtGameTime,
                           Map<UUID, Rank> ranks, int treasury, Tier tier,
                           List<BuildingRecord> buildings, List<WorkerRecord> workers) {
    // compact ctor: requireNonNull on all fields; treasury >= 0 else IAE;
    //   ranks/buildings/workers defensively copied with Map.copyOf/List.copyOf;
    //   ranks must not contain the owner, OWNER or VISITOR values (IAE)
    public static VillageState founded(HeartLocation heart, UUID owner, String ownerName, long gameTime); // HAMLET, 0, empty
    public Rank rankOf(UUID player);              // owner → OWNER; ranks lookup; else VISITOR
    public VillageState withRank(UUID player, Rank rank);  // VISITOR removes the entry; OWNER or owner's uuid → IAE
    public VillageState withTreasury(int emeralds);         // IAE if < 0
    public VillageState depositTreasury(int emeralds);      // IAE if < 0; Math.addExact → ArithmeticException on overflow
    public boolean isHeartAt(HeartLocation loc);
}

public final class WorldClaim {   // the "one village per world" rule holder; mutable, owned by the saved data
    public WorldClaim();                                  // empty
    public WorldClaim(Optional<VillageState> village);
    public Optional<VillageState> village();
    public ClaimRules.Result evaluate(double distanceToBell);           // delegates to ClaimRules.evaluate(d, village.isPresent())
    public ClaimRules.Result claim(HeartLocation at, UUID owner, String ownerName, double distanceToBell, long gameTime);
                                                                        // stores VillageState.founded only on CLAIMED
    public Optional<VillageState> releaseAt(HeartLocation at);          // only if at equals the claim; returns the released state
    public BreakDecision mayBreakHeart(HeartLocation at, UUID player);  // enum BreakDecision { ALLOWED_UNCLAIMED, ALLOWED_OWNER, DENIED_NOT_OWNER }
    public void update(UnaryOperator<VillageState> f);                  // ISE if no village
    public void clear();                                                // test support and admin use
    // equals/hashCode over village
}
```

`ClaimRules` keeps its current signature and enum, so `MAX_BELL_DISTANCE` remains the single
source for the 16-block rule.

### 3.3 Serialisation (glue, `dev.villageheart.world`, DFU only, still unit-testable)

`VillageCodecs` (no `net.minecraft` imports, only `com.mojang.serialization.*`):

- `UUID_STRING`: `Codec.STRING.comapFlatMap(s -> try UUID.fromString → DataResult.success / error, UUID::toString)`
- `TIER`, `RANK`: `Codec.STRING.comapFlatMap(` lowercase name → enum, unknown → `DataResult.error` `, e -> e.name().toLowerCase(Locale.ROOT))`
- `HEART_LOCATION`: `RecordCodecBuilder` with `dim` (string), `x`, `y`, `z` (ints)
- `BUILDING` (`type`, `marker`), `WORKER` (`villager`, `job`)
- `VILLAGE_STATE`: `RecordCodecBuilder` (9 fields, under the 16 limit). Field names are **pinned** and
  are part of the save format:
  `heart`, `owner`, `owner_name`, `claimed_at` (Codec.LONG), `ranks`
  (`Codec.unboundedMap(UUID_STRING, RANK)`, `optionalFieldOf("ranks", Map.of())`), `treasury`
  (`optionalFieldOf(…, 0)`), `tier` (`optionalFieldOf(…, HAMLET)`), `buildings` and `workers`
  (`.listOf().optionalFieldOf(…, List.of())`).
  Collections are optional so that a file from an older build still loads.
- `WORLD_CLAIM`: `{ "schema": int (=1), "village": optional VILLAGE_STATE }` → `WorldClaim`.
  `schema` is written now, so a later milestone can migrate. Decoding ignores it in M1.

`VillageSavedData extends net.minecraft.world.level.saveddata.SavedData` (`dev.villageheart.world`):

- **[verified]** Passing `null` for `DataFixTypes` is safe: vanilla `readTagFromDisk` calls

  `DimensionDataStorageMixin.handleNullDataFixType` skips the fixer when it is null. The save/reload

- File: `<world>/data/villageheart_village.dat`. The overworld's data dir is
  `DimensionType.getStorageFolder(Level.OVERWORLD, server.getWorldPath(LevelResource.ROOT)).resolve("data")`
  **[verified]**, the same path `ServerChunkCache` builds (`getDimensionPath(dim).resolve("data")`).
- Every mutator calls `setDirty()`: `claim(...)`, `releaseAt(...)`, `update(...)`, `clear()`. There is

### 3.6 GameTest isolation (new infrastructure, needed by every later milestone)

**Problem.** The claim is global (one per world). Vanilla 1.21.11 groups GameTests into batches **by
test environment**, at most 50 per batch, and runs every test in a batch **at the same time**.
Batches run one after another (`GameTestBatchFactory.divideIntoBatches` groups with
`Collectors.groupingBy(environment)` **[verified]**). Two claim tests in the same batch would see
each other's claim and fail at random.

**Solution.** Every test that reads or writes the village claim declares its **own** test
environment. Add one JSON per such test under
`src/gametest/resources/data/villageheart-gametest/test_environment/<name>.json`, each containing
`{"type": "minecraft:all_of", "definitions": []}` (a copy of vanilla's
`data/minecraft/test_environment/default.json` **[verified]**). The test then uses
`@GameTest(environment = "villageheart-gametest:<name>")`. Fabric's annotation has
`String environment()` (default `minecraft:default`) **[verified]**.

`dev.villageheart.gametest.VillageTestSupport` (gametest source set):
- `reset(GameTestHelper h)`: `VillageClaims.data(server).clear()`. **Every claim test calls this first.**
  It is needed because the GameTest world (`build/run/gameTest/world`) may persist between runs, and
  an earlier test that failed may have left a claim behind.
- `ServerPlayer player(GameTestHelper h, GameType mode)`: `h.makeMockServerPlayerInLevel()` **[verified:
  a real ServerPlayer with a random UUID, named `test-mock-player`, added to the player list, whose
  `gameMode()` override returns CREATIVE]**, then `p.setGameMode(mode)` **[verified]**. Mock
  players are tracked so that `done(h)` can remove them with `server.getPlayerList().remove(p)`
  **[verified]**.
- `void place(GameTestHelper h, ServerPlayer p, BlockPos relBelow)`: puts a Heart stack in the main
  hand (`p.setItemInHand(MAIN_HAND, stack)`), then calls `h.placeAt(p, stack, relBelow, Direction.UP)`.
  **Gotcha [verified bytecode]:** `placeAt` builds a `UseOnContext(player, MAIN_HAND, hit)` whose
  item comes from the *player's hand*, not from the stack argument. It hits `relBelow.relative(UP)`,
  and because that block is air (replaceable), the block is placed **at `relBelow.above()`**.
- `void done(GameTestHelper h)`: `reset`, remove mock players, `h.succeed()`.
- Survival placement is needed to prove the item is not consumed. After `setGameMode(SURVIVAL)`,
  assert `!p.hasInfiniteMaterials()` **[verified method]** as a precondition, so that the test is
  not silently made meaningless by the creative override.
- Breaking as a player: `boolean ok = p.gameMode.destroyBlock(absPos)` **[verified: `public final
  ServerPlayerGameMode gameMode`, `destroyBlock(BlockPos)` returns boolean and runs the full path:
  canDestroyBlock → BEFORE event → playerWillDestroy → removeBlock → destroy → drops]**. Use an
  empty or Heart-holding hand. A sword in creative cannot break blocks.

**Fallback** if custom environments do not load from the gametest mod's resources (the server
fails at start with an unknown environment id): put all claim scenarios into **one** `@GameTest`
that chains them with `helper.startSequence().thenExecute(..).thenIdle(n)...thenSucceed()`
**[verified methods]**. Record which approach worked in `docs/TESTING.md`.

**T-L1-3 `WorldClaimTest`** (the L1 "ClaimRules refuses when a claim exists" criterion, at the stateful level):
- `firstClaimStoresVillage`: `claim(locA, alice, "alice", 3, 100) == CLAIMED`, `village()` present, heart locA, owner alice, claimedAt 100.
- `secondClaimRefusedAndFirstUntouched`: then `claim(locB, bob, …, 3, …) == ALREADY_HAVE_VILLAGE`, and the village still equals the first state (same `equals`). Fails if the second claim overwrites the first.
- `sameOwnerSecondClaimAlsoRefused`: alice claiming at locB gives ALREADY_HAVE_VILLAGE.
- `refusedClaimStoresNothing`: `claim(locA, alice, …, -1, …) == NO_BELL_NEARBY` and `village()` is empty.
- `releaseOnlyAtClaimedLocation`: `releaseAt(locB)` is empty and the claim is kept. `releaseAt(locA)` returns the state and then `village()` is empty. Fails if release ignores the position (which would let any Heart break release the village).
- `reclaimAfterReleaseIsFresh`: claim, `update(v -> v.depositTreasury(9).withRank(carol, STEWARD))`, release, then claim by bob → treasury 0, no ranks, owner bob.
- `breakDecisions`: unclaimed location → ALLOWED_UNCLAIMED (including when a village exists elsewhere), claimed location + owner → ALLOWED_OWNER, claimed location + other → DENIED_NOT_OWNER.
- `dimensionIsPartOfLocation`: the same x/y/z in `minecraft:the_nether` is not the claimed Heart (`releaseAt` is empty, `mayBreakHeart` gives ALLOWED_UNCLAIMED).

**T-L1-4 `VillageCodecsTest`** (`src/test/java/dev/villageheart/world/`, `JsonOps.INSTANCE`): the L1 "VillageState round-trips through its serialisable form with no data loss" criterion.

Fails on any dropped or truncated field.

- `roundTripFoundedState` (all collections empty).
- `pinnedFieldNames`: the encoded JSON object has exactly the keys `heart, owner, owner_name, claimed_at, ranks, treasury, tier, buildings, workers`, and the world object has `schema = 1`. This protects the save format from an accidental rename. Fails if a key changes.

## 6. Risks and unknowns

1. **(Top risk) GameTest concurrency vs one global claim.** Tests in the same batch run at the same
   time, so claim tests would interfere with each other and fail at random. The per-test
   `test_environment` approach depends on Fabric/vanilla loading `test_environment` JSONs from the
   gametest mod's resources. This is inferred from the registry (`Registries.TEST_ENVIRONMENT` id
   `test_environment`, and vanilla ships `data/minecraft/test_environment/default.json`) but not yet
   run. Step 5 proves it with probe tests, and §3.6 gives the fallback. Every later milestone
   inherits this rule, so record it in `docs/TESTING.md`.
2. **Client ghost item on refused placement** (survival). Vanilla does not resync the hand after a
   server-side refusal. `sendAllDataToRemote()` should fix it, but there is no automated proof (manual
   check). If it misbehaves, the fallback is to allow placement and immediately remove the block and
   return the item. Do not switch silently: record the change.
3. **Null `DataFixTypes`** relies on Fabric's `DimensionDataStorageMixin`. If a future Fabric API drops
   it, loading NPEs. T-L2-6 catches this. Do not "fix" it by choosing an unrelated vanilla `DataFixTypes`
   value, because that would run the wrong fixers over our data.
4. **`affectNeighborsAfterRemoval` is not universal** (it is skipped without `UPDATE_NEIGHBORS`). This is
   covered by the self-heal (rule 6, T-L2-8). Do not add a mixin on `LevelChunk.setBlockState`.
5. **Double release.** The owner's break could release through two paths if the builder also adds
   release to `playerWillDestroy` or `PlayerBlockBreakEvents.AFTER`. Only `affectNeighborsAfterRemoval` and
   the self-heal may release. T-L2-5 (exactly 70 emeralds) catches double drops.
6. **The mock ServerPlayer's game mode.** `makeMockServerPlayerInLevel` overrides `gameMode()` to CREATIVE
   no matter what. `setGameMode(SURVIVAL)` updates the abilities, which is what item consumption uses.
   The preconditions in the tests (`hasInfiniteMaterials()`) make a wrong assumption fail loudly
   instead of passing vacuously.
7. **Mapping churn.** 1.21.11 renamed ResourceLocation to `Identifier` (`ResourceKey.identifier()`, `Identifier.parse` **[verified]**).
   Older tutorials and AI memory use `location()` / `ResourceLocation`, and also `onRemove` (replaced by
   `affectNeighborsAfterRemoval`) and `PersistentState`/`Type(..., DataFixTypes)` from Yarn. Trust the javap output here.
8. **Owner gone forever** (multiplayer): nobody can break the Heart. Ops can still `/setblock` it away,
   which releases through the removal hook. Ownership transfer is M24. Note this in DESIGN later if it
   becomes a problem.
9. **Persistent GameTest world** across runs: `reset` at the start of every claim test handles it.
