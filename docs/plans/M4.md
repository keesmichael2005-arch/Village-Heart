## 1. Goal

When the game asks "is the room behind this marker a valid building?", a flood fill of air starting just inside the marked
door answers it: enclosed or not, how much air, how much floor, which blocks are inside (beds, chests, composters, torches,
...) with their positions, and, if it fails, one clear reason with a position, such as *"Roof missing at (12, 70, -4)"* or
*"Wall gap at (3, 65, 8)"*. Nothing player-visible changes yet: M5 calls the scanner from markers and turns the result into
grey/red/green. M4 delivers the scanner (pure core, unit-tested) and its real-world adapter (glue, GameTested).

### Dependency on M3: none at the code level
The scanner's entry point takes **a marker position plus the outward direction** (`core.room.Dir`, or `net.minecraft.core.Direction`
in the glue facade). It never reads a marker block: the marker cell may be air. M4 tests pass the position and direction where
a marker would hang. That direction is exactly M3's `FACING` (out of the wall), so M5 calls
`RoomScans.scan(level, markerPos, state.getValue(MarkerBlock.FACING))`. M4 can be built and merged before or after M3.

## 3. Design

### 3.1 Core types (pure Java, package `dev.villageheart.core.room`)

```java
/** A block position. toString() is "(x, y, z)", the format every reason uses. */
public record Pos(int x, int y, int z) implements Comparable<Pos> {   // order: x, then y, then z
    public Pos offset(Dir d);            // one step
    public Pos above(); public Pos below();
    public long pack();                  // 26/12/26 bits like BlockPos.asLong: x,z in [-33554432, 33554431], y in [-2048, 2047]
    public static Pos unpack(long v);
    @Override public String toString();  // "(12, 70, -4)"
}

/** The six directions. Names equal net.minecraft.core.Direction's, so glue maps with Dir.valueOf(direction.name()). */
public enum Dir { DOWN, UP, NORTH, SOUTH, WEST, EAST;   // NORTH = -z, SOUTH = +z, WEST = -x, EAST = +x
    public final int dx, dy, dz;
    public Dir opposite(); public boolean horizontal();
    public Dir clockwise();              // horizontal only (seen from above): NORTH→EAST→SOUTH→WEST; throws for UP/DOWN
    public Dir counterClockwise();
}

public enum CellKind { OPEN, SOLID, UNLOADED }
public enum DoorPart { NONE, LOWER, UPPER }

/**
 * What one block position means to the scanner. Instances are immutable and shared (the adapter caches one per BlockState),
 * so cell() allocates nothing.
 *   kind     OPEN: the fill passes (air, torches, flowers, water, open-collision blocks)
 *            SOLID: wall/floor/roof/furniture: the fill stops; it is part of the room's shell
 *            UNLOADED: the adapter cannot see this position (chunk not loaded): the scan fails
 *   door     which half of a door this is (doors are always SOLID)
 *   contents content keys for this block (see 3.3), already de-duplicated for two-block things
 */
public record Cell(CellKind kind, DoorPart door, List<String> contents) {
    public static final Cell OPEN = …, SOLID = …, UNLOADED = …;   // no contents
    public static Cell open(String... contents); public static Cell solid(String... contents);
    public static Cell door(DoorPart part, String... contents);
}

/** Read-only world access for the scanner. Coordinates are absolute. */
public interface BlockView {
    Cell cell(int x, int y, int z);
    /** True when nothing SOLID is above (x, y, z), i.e. the position is outdoors. Only asked for OPEN cells. */
    boolean openToSky(int x, int y, int z);
}
```

`Balance.ROOM_MAX_AIR = 4096` (DESIGN §3.2; the plan treats it as tunable like every other number).

### 3.2 The scan (`RoomScanner`, static, no state)

```java
public static RoomScan scanFromMarker(BlockView view, Pos marker, Dir outward);
public static RoomScan scanFromDoor(BlockView view, Pos doorLower, Dir inward);   // used by scanFromMarker and by tests
```

**Door search** (`scanFromMarker`). `support = marker.offset(outward.opposite())` is the wall block the marker hangs on. DESIGN §3.1:
the marker is "above (or beside) a door". Candidates, in this order, with `cw = outward.clockwise()`, `ccw = outward.counterClockwise()`:

1. `support.below()` (marker above the door)
2. `support.offset(cw)`, 3. `support.offset(ccw)` (beside, at the same height)
4. `support.offset(cw).below()`, 5. `support.offset(ccw).below()` (beside, marker one block higher)

The first candidate whose cell has `door != NONE` wins. An `UPPER` half is normalised to its lower half (`c.below()`, which must be
`LOWER`, otherwise the candidate is skipped). No candidate → problem `NO_DOOR`, no fill. Only doors count (DESIGN §3.2 "Has a door
at the marked doorway"); fence gates and trapdoors do not satisfy it (they still count as wall).

**Start cell.** `inward = outward.opposite()`. `start = doorLower.offset(inward)`; if that cell is not OPEN, try
`doorLower.above().offset(inward)`; if neither is OPEN → problem `DOORWAY_BLOCKED` at the first one, no fill.

**Fill** (breadth-first, FIFO, neighbour order = `Dir.values()` order, so results are deterministic):

```
if openToSky(start)                      → leak(E = start, P = null)
interior = {start}; queue = [start]
while queue not empty:
  c = poll
  for d in Dir.values():
    n = c + d; skip if n in interior or n in shell
    cell = view.cell(n)
    UNLOADED → problem NOT_LOADED at n; stop
    SOLID    → shell.add(n); record cell.contents at n; continue
    OPEN     → if view.openToSky(n): leak(E = n, P = c); stop
               interior.add(n); record cell.contents at n
               if interior.size() > Balance.ROOM_MAX_AIR: problem TOO_BIG; stop
               queue.add(n)
```

- **4096 cap**: a room of exactly 4096 interior cells is fine; the 4097th cell fails with `TOO_BIG`. The fill never visits more
  than 4097 interior cells, so the worst case is bounded.
- The fill stops at the **first** problem; one reason at a time is enough (the player fixes it and the next re-check finds the next).
- `volume` = `interior.size()` (all OPEN cells, so torches and water count as air).
- **Floor area** = the number of distinct `(x, z)` columns that contain at least one interior cell whose cell **below** is not
  OPEN. A 5×5 room gives 25. A bed or chest on the floor still counts (the cell above it stands on it). A second storey over the
  same footprint does not add area; a column filled floor-to-ceiling with furniture does not count.
- **Contents** are recorded for every interior cell and every **shell** cell (SOLID cells 6-adjacent to the interior). Full-block
  furniture (barrel, smoker, crafting table) and non-full furniture (chest, bed, composter) are all SOLID, so they are found in
  the shell. Consequences, documented and tested: a chest built into the wall with its front outside still counts; a chest on the
  far side of a one-block wall does not; a block in a wall shared by two rooms counts for both (M6 must de-duplicate stockpile
  chests by position).
- On failure the result still carries the partial volume and contents, with `enclosed = false`.

**Leak localisation** (`leak(E, P)`, pinned rule; E is the first discovered OPEN cell open to the sky, P the cell it was reached from):

1. `P == null` (the start itself is outdoors): climb from `start.above()` up to 64 cells while OPEN; the first cell with ≥2 non-OPEN
   horizontal neighbours is the hole H → `ROOF_MISSING` at H; none found → `ROOF_MISSING` at `start`.
2. Otherwise P is covered (something SOLID is above it). Let `ceil` = the y of the first non-OPEN cell above P (scan up to 64; none →
   step 4). Let `H = (E.x, ceil, E.z)`: the cell beside P's ceiling, in E's column.
3. If H is OPEN and has ≥2 non-OPEN horizontal neighbours, H is a hole in the roof plane → `ROOF_MISSING` at H.
4. Otherwise the fill walked out sideways → `WALL_GAP` at P.

Why this works for the common cases (E is always reached by a horizontal step, because the cell above a covered cell is covered):
- Roof hole: E is the room cell under the hole, P the room cell next to it, `ceil` the roof, H the missing roof block itself, with roof
  blocks on 4 (1×1 hole), 3 (1×2) or 2 (2×2 corner) sides → **ROOF_MISSING at the broken roof block** (the L2 acceptance asks for
  "that position").
- Wall gap: P is the gap cell (covered by the lintel), E the outdoor cell beyond it, H the outdoor cell beside the lintel, with one
  non-OPEN neighbour → **WALL_GAP at the gap**. An empty 2-high doorway reports its lower cell.

Known misreports, accepted and documented (the position is still at the opening): a wall gap opening into a 1-wide alley or an
outside corner reads as `ROOF_MISSING` at the outdoor cell beside the lintel; the edge of a 3×3 or larger roof hole reads as
`WALL_GAP` at the room cell next to it; a lantern hanging under the ceiling at P's column lowers `ceil`. A floor hole in a room that
floats over air reads as a `WALL_GAP` under the floor; rooms on the ground do not have this case (a floor hole into a sealed pit just
makes the pit part of the room). Underground or under-overhang leaks never see the sky and end as `TOO_BIG`.

### 3.3 Results

```java
public record RoomProblem(Kind kind, @Nullable Pos pos) {
    public enum Kind { NO_DOOR, DOORWAY_BLOCKED, ROOF_MISSING, WALL_GAP, TOO_BIG, NOT_LOADED, SHARED }
    public String message();
}
```

| Kind | `message()` (exact) | pos |
|---|---|---|
| `NO_DOOR` | `No door below or beside the marker` | the marker |
| `DOORWAY_BLOCKED` | `Doorway blocked at (x, y, z)` | the inside cell in front of the door's lower half |
| `ROOF_MISSING` | `Roof missing at (x, y, z)` | H (the hole), see 3.2 |
| `WALL_GAP` | `Wall gap at (x, y, z)` | P |
| `TOO_BIG` | `Room too big (max 4096 air)` (number from `Balance`) | null |
| `NOT_LOADED` | `Room reaches an unloaded area at (x, y, z)` | first UNLOADED cell |
| `SHARED` | `Room is shared with the marker at (x, y, z)` | the other marker (lowest by `Pos` order when several) |

DESIGN §3.2's example says *"Roof missing above (12, 70, -4)"*; M4 reports the hole itself, so the builder updates that example to
*"Roof missing at …"*. Messages stay English strings in core; M5 may map `kind` + `pos` to translation keys.

```java
public record RoomScan(
    @Nullable Pos marker,          // null for scanFromDoor
    @Nullable Pos door,            // lower half of the door used, null when NO_DOOR
    @Nullable Pos start,
    boolean enclosed,              // fill finished without NOT_LOADED/leak/TOO_BIG (and door + start found)
    int volume, int floorArea,
    Map<String, List<Pos>> contents,   // key → positions in discovery order; TreeMap by key; unmodifiable
    List<RoomProblem> problems,        // empty when valid
    Set<Long> interior, Set<Long> shell,  // packed positions, unmodifiable; M20 uses them for overlap checks
    long roomKey                       // min packed interior position; equal for any two enclosed scans of the same room
) {
    public boolean valid();            // enclosed && problems.isEmpty()
    public int count(String key);      // contents.getOrDefault(key, List.of()).size()
    public List<Pos> positions(String key);
    public boolean contains(Pos p);    // interior
    public boolean occupies(Pos p);    // interior or shell (for M20: a blueprint site must not overlap a player room)
    public RoomScan withProblem(RoomProblem p);   // copy with one more problem (used by SharedRooms)
}
```

**Content keys** (constants in `core.room.RoomContents`): a namespaced block id for every non-air block (`"minecraft:chest"`,
`"minecraft:composter"`, `"villageheart:chopping_block"`), plus group keys starting with `#`:

| Key | Meaning (decided by the adapter) |
|---|---|
| `#bed` | any bed, counted on its HEAD half only |
| `#door` | any door, counted on its LOWER half only |
| `#chest` | any `ChestBlock` (chest, trapped chest, the copper chests); not the ender chest |
| `#light` | `state.getLightEmission() > 0` at scan time |

Two-block things report their block id once: the adapter emits no id for the `BED_PART=FOOT` half or the `DOUBLE_BLOCK_HALF=UPPER`
half (doors, tall plants). A double chest is two chests (each block is one chest with its own inventory); M5 decides whether
"≥2 chests" means blocks, and this plan recommends blocks. Contents positions are what M6 (stockpile chests) and M7 (one worker
slot per job block) need.

**Shared rule** (`SharedRooms`, pure):

```java
/** For every enclosed scan whose roomKey equals another enclosed scan's, add SHARED pointing at the other marker. */
public static <K> Map<K, RoomScan> apply(Map<K, RoomScan> scansByMarker);
```

Enclosed fills are whole connected components of OPEN cells, so two scans of one room have identical interior sets and the same
`roomKey`; two different rooms are disjoint. Non-enclosed scans are never marked shared (they are already invalid). M5 calls this
over the latest scan of every building after each round-robin step.

### 3.4 Glue (package `dev.villageheart.room`)

**`RoomCells`**: `static Cell of(BlockState state)`, cached per state in a `ConcurrentHashMap<BlockState, Cell>` (server thread only, but
cheap insurance), cleared on `ServerLifecycleEvents.END_DATA_PACK_RELOAD` **[verified: `(server, resourceManager, success)`]** and on
`SERVER_STARTING`, because tags (beds, doors, fence gates) can change on `/reload`. Registered from `VillageHeart.onInitialize`.

Classification (DESIGN §3.2: "doors, glass, panes, fences, trapdoors and slabs count as wall"):

```
if state.isAir()                                              → Cell.OPEN
shape = state.getCollisionShape(EmptyBlockGetter.INSTANCE, BlockPos.ZERO)   [verified: BlockStateBase, uses the per-state cache]
kind  = (shape.isEmpty() && !state.is(BlockTags.FENCE_GATES)) ? OPEN : SOLID
door  = state.is(BlockTags.DOORS) ? (state.getValue(DoorBlock.HALF) == LOWER ? LOWER : UPPER) : NONE
contents = id (unless FOOT/UPPER half) + groups (3.3)
```

The rule is "anything with a collision box is wall". That covers every material the design lists without a tag list: glass and
glass panes, fences, walls, iron and copper bars, doors (open or closed), trapdoors (open or closed), slabs, stairs, leaves. The one
exception is the **open fence gate**, whose collision shape is empty **[verified: `FenceGateBlock.getCollisionShape` returns
`Shapes.empty()` when OPEN]**, hence the `FENCE_GATES` tag. Consequences (pinned by T-L2-3): torches, buttons, pressure plates,
signs, rails, flowers, cobwebs, vines, water, one-layer snow and powder snow (empty collision with an empty context **[verified]**)
are holes; carpets, beds, chests, lanterns and flower pots plug a hole. Blocks with a dynamic shape (scaffolding, shulker boxes) are
classified by their empty-context shape, which is deterministic per state.

APIs: `BuiltInRegistries.BLOCK.getKey(block)` returns `net.minecraft.resources.Identifier` (1.21.11 rename of `ResourceLocation`)
**[verified]**, `.toString()` gives `minecraft:chest`. `BedBlock.PART`/`BlockStateProperties.BED_PART`, `DoorBlock.HALF`/
`BlockStateProperties.DOUBLE_BLOCK_HALF` **[verified]**, `state.hasProperty(...)`, `state.getLightEmission()` **[verified]**,
`CopperChestBlock extends ChestBlock` and `EnderChestBlock` does not **[verified]**.

**`LevelBlockView implements BlockView`** over a `ServerLevel`:

```
cell(x,y,z):   y < level.getMinY() → Cell.SOLID (nothing passes below the world)
               y > level.getMaxY() → Cell.OPEN
               chunk = level.getChunkSource().getChunkNow(x >> 4, z >> 4)   // cached: last chunk key + LevelChunk
               chunk == null → Cell.UNLOADED
               return RoomCells.of(chunk.getBlockState(mutablePos.set(x, y, z)))
openToSky(x,y,z): y > level.getMaxY() → true; chunk == null → false;
               return y > chunk.getHeight(Heightmap.Types.MOTION_BLOCKING, x & 15, z & 15)
```

- `ServerChunkCache.getChunkNow(int, int)` returns a FULL `LevelChunk` or null and **never loads a chunk**; it returns null on any
  thread other than the server thread **[verified]**. Scans must run on the server thread (all callers are ticks or block events).
- `ChunkAccess.getHeight(Types, x, z)` returns `firstAvailable - 1`, the y of the top motion-blocking block **[verified]** (unlike
  `Level.getHeight`, which adds 1). `MOTION_BLOCKING` = `blocksMotion() || has fluid` **[verified]**; `blocksMotion` is the legacy
  `isSolid` (collision box at least ~0.73 average size or full height). So glass, panes, slabs, stairs, closed and open trapdoors,
  fences and leaves cover the sky; a carpet roof would not (accepted, see risks).

**`RoomScans`** (facade, the API M5 calls):

```java
public static RoomScan scan(ServerLevel level, BlockPos marker, Direction outward);   // Dir.valueOf(outward.name())
public static Pos pos(BlockPos p); public static BlockPos blockPos(Pos p);
```

No saved data, no networking, no assets, no commands in M4.

### 4.1 FakeGrid (step 2)

A sparse `HashMap<Long, Cell>`; every unset position is `Cell.OPEN`. `openToSky(x, y, z)` is true when no non-OPEN cell exists in that
column above y; it keeps a per-column "highest non-OPEN y" map updated on `set` (recomputed for that column when a cell is set to
OPEN), so the perf test measures the scanner, not the grid. Optional `unloadedBeyondX(int x)` makes every `x > limit` UNLOADED.
Builders:
- `box(x0,y0,z0, x1,y1,z1, Cell)` fills a solid box; `hollow(x0,y0,z0, x1,y1,z1, Cell wall)` makes a shell (floor, walls, roof) with
  OPEN inside;
- `door(x, y, z)` sets `Cell.door(LOWER, "minecraft:oak_door", "#door")` at y and `Cell.door(UPPER)` at y+1;
- `set(x, y, z, Cell)`, `clear(x, y, z)` (to OPEN).
Standard fixture `room5x5x3()`: shell `hollow(0,0,0, 6,4,6, solid("minecraft:stone"))` (interior x,z 1..5, y 1..3 = 75 cells), door
at (3,1,0)/(3,2,0), marker at (3,3,-1) with `outward = NORTH`. Start is (3,1,1).

## 6. Risks and unknowns

1. **Top risk: leak localisation is a heuristic.** The pinned rule (3.2) is exact for single holes in roofs and walls, which is what
   the acceptance tests and most players hit, but irregular cases (alleys, big roof holes, hanging lanterns) give the right
   position with the wrong word. Mitigation: every reason carries a position at the opening; T-L1-2/-3 sweep every roof and wall cell
   of the fixture, so a regression in the common case is caught. Revisit in M5 if the screenshots/chat show confusing text.
2. **Sky test vs wall rule mismatch.** "Open to sky" uses the `MOTION_BLOCKING` heightmap (legacy `isSolid`), the wall rule uses the
   collision box. They disagree only for thin blocks (a roof made of carpets reads as open sky) and dynamic-shape blocks. Accepted.
3. **Lenient wall rule.** Carpets, beds, chests and lanterns plug holes. This follows "anything you cannot walk through", is pinned
   by T-L2-3, and can be tightened later with a `villageheart:room_open` tag if players abuse it (not in M4).
4. **GameTest barriers.** Without `skyAccess = true` room leak tests pass for the wrong reason (5.2). Every leak test also has a
   control assertion that the leak is detected, so a missing `skyAccess` fails loudly instead of silently.
5. **Real-world cost.** One scan touches up to ~4097 interior + ~6×4097 neighbour lookups; with the last-chunk cache and per-state
   `Cell` cache that is well under a millisecond for normal rooms, but M5 runs one scan per second inside the 1 ms/tick budget. M5
   should wrap scans in `VillageTicker.section()` / a `VillageSystem` so layer 3 measures them.
6. **Shared walls double count contents** (3.2). M6 must key stockpile chests by position.
7. **Round-robin staleness.** `SharedRooms` compares the latest scans, which may be up to `buildings × 1 s` apart; M5's concern.
8. **`#light` flickers** for blocks whose light depends on state (furnaces, campfires, redstone lamps). M5 decides whether a lit
   furnace counts as the House light source.
9. **M3 contract.** If M3 ships `FACING` with a different meaning than "out of the wall", only the M5 call site changes; the scanner
   API takes the outward direction explicitly.
