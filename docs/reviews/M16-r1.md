## Hidden-miner state (NoAI, Invisible, Invulnerable, Silent)
I read every path that hides or surfaces a miner: `AwayTrips.hide/surface/release`, `processLoaded`, the RETRY set, the ENTITY_LOAD re-apply, the conversion handler,
`Workers.fire/fireById/restoreVanilla/restoreAfterRelease`, the `WorkerSystem` orphan sweep and the `MinerSystem` steps.
I also ran three probes as a temporary class `VerifierProbes`, which I removed afterwards:
- **Release the Heart while the miner is unloaded, then load it.** It comes up on the first tick, all four flags are off, and it is a vanilla villager again. The orphan sweep calls `restoreVanilla`, which calls `release`.
- **Fire while it is away (loaded), then reload.** It is up after the fire and still up after the reload.
- **Surface spot and every cell within 3 of the marker blocked, rails removed, then the Heart released.** It stays hidden, as documented ("with none it stays hidden"). Once the cells are cleared it comes up with all flags off within 40 ticks, through the RETRY set.
  So the state recovers and is not stuck for good. See note 1 for what the Heart shows meanwhile.
The existing tests already cover the other paths: fire while loaded, fire by id while unloaded then load, release while loaded, witch conversion, a broken trip and the name tag.
A zombie conversion cannot start, because the hidden miner is invulnerable. Death needs `/kill` or the void; the record is then fired and nothing has to be restored.
