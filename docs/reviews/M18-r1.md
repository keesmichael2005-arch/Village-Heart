## Gates (user decision: hired workers and guards open gates, mobs cannot)

`WalkNodeEvaluatorMixin` redirects only the first `getPathType` in `getPathTypeWithinMobBB`.
- It reports a closed gate as `DOOR_WOOD_CLOSED` only when `GatePaths.mayPass` holds: a hired adult villager, a gate in the claim, no redstone power, and no hostile within 8 blocks unless the walker is an engaged guard.
- The per-level `PathTypeCache` is read before the redirect, so it is not poisoned.
- `defaultRequire 1` makes a broken injection fail loudly.
- `GateTraffic` opens the gate and `GateKeeper` closes it. The open list is saved in the `GateLedger` (`villageheart_gates`).

**Never left open:**
- A fired and discarded walker: proven, the gate closes within 40 ticks.
- A restart: simulated with `forgetAgesForTests`, and the ledger codec is covered by `GateLedgerTest`. A real save/reload is not tested (BACKLOG).
- **Gap:** the keeper is a `VillageSystem`, so it only ticks while a village is claimed. A gate that is open when the Heart is removed stays open (BACKLOG).

**Zombies cannot pass:** proven (`createPath` from the zombie cannot reach).

**Unhired villagers:** see fix item 4. The test only proves that an unhired villager is kept out *while a zombie is near*, which the hostile rule would do for a hired worker as well.
