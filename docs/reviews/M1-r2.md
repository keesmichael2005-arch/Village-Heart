   POIs. Round 1 asked for this explicitly: "Call `poi.remove` only for POIs whose block is no longer a POI block". `done()` runs
   `reset` → `purgePoi` at the **end** of every claim test, so every M7+ claim test that places a workstation or a bed will log
   this ERROR, and the POI will be gone while its block still stands.

   called `VillageTestSupport.reset(h)` as `done()` does, then set the composter to air →
   `[Server thread/ERROR] POI data mismatch: never registered at BlockPos{...}`. Control: the same test without the `reset`
   call logged nothing. Both temporary files were deleted afterwards.
   Expected: only touch what the claim tests need. Purge `PoiTypes.MEETING` POIs only (bells, which are what leak into the
   16-block check): set the bell block to air when it is still a bell, and call `poi.remove` only when the block at the POI
   position is no longer a block of that POI type (an orphan). Leave every other POI alone. Add a regression probe like the
   one above (a POI block, then `reset`/`done`, then the block removed) and confirm 0 `POI data mismatch` lines.
