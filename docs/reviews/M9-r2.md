### Test changes judged for weakening
- **`4abfd37`: `sixOaksTwoDays` uses `assertNoGiveUpsAt(bases)` in place of `assertNoGiveUps`.** This is not a weakening of a roadmap criterion. The no-give-up check is a new guard beyond the roadmap, and the roadmap asserts (16 logs, replant per oak, wall whole) are unchanged.
  - The match is exact: the `HeartLocation` record's `toString` ends in `]`, and the tree key is the base cell, which equals `growOak`'s returned position. So the check is not vacuous.
  - The stated reason does not fit what the check does. A regrown tree stands on the same base cell as the original, so its give-up still fails this check. The helper only ignores give-ups at other cells, and in this test no tree can stand on another cell. Note 3.
- **L1 `rows5and6_replantBeforeCollectBeforeANewFell` → `rows5to8_replantBeforeAFellBeforeCollect`.** This is a deliberate change of the planner's order, not a weakened test.
  - The old expectations (COLLECT ahead of FELL_NEW and FELL_TASK) are replaced by the new order.
  - The new test adds cases that pin the edges: collect with an exhausted finder, collect at day time 5000, and collect with no axe (NEEDS_TOOL).
  - `row8` gains a `.collect()`, which makes it stronger: it pins that a task beats a drop after 5000.
  - The change is documented in plan §8 #17 and PROGRESS. The roadmap and DESIGN do not fix the order. Note 4 covers the despawn side effect.
- **Sticky sampler flags in `oddShapesFelledWhole`** (from `86ff136`, round 0). These are acceptable. "Felled whole" is still asserted: every initial log of each tree was gone at some tick. Only the "still gone at the end" reading is dropped, and a regrown sapling makes that reading false while the behaviour is correct. Nothing else in the test removes logs, so the flag cannot be set without felling.

## Non-blocking notes
1. **`WalkTo`'s gap-restart block is not pinned.** If it is removed, 2 of 2 full runs stay green. It matters when a walk resumes after a deposit trip of more than 800 ticks.
   A GameTest could cover it: a worker yields to a long trip in the middle of a walk, then must not give up.
2. **The path re-plan has only a statistical guard.** With the fix removed, 1 of 4 runs fails. A deterministic GameTest would be cheap: open a door on the worker's path and assert that the navigation's path is the long one again within a few ticks.
3. **`assertNoGiveUpsAt`'s Javadoc and the PROGRESS line give a wrong reason.** They say "a regrown canopy can wall off its own trunk" and that the worker rightly gives such a tree up. A regrown tree has the same base, and so the same key, as the original, so that give-up would still fail the test.
   Either reword the reason, or, if a regrown tree really can be walled off, expect that test to flake.
4. **Planner order and despawn.**
   - Under the new order, drops are only collected when no tree is available, or after day time 5000.
   - In a large forest the finder always has a tree until 5000. Drops from a tree felled at day time ~1000 despawn at ~7000, so they get only the window from 5000 to their despawn.
   - That may cost saplings in big forests. The tests have six trees, felled in about 2 000 ticks, so they do not exercise it.
   - Worth a look in M16-style simulation, or a cap on how long a drop may wait.
   - Plan table row T-L1-9 still says "replant before collect before a new fell". §8 #17 records the change.
5. The `ToolKind` Javadoc still names the removed `status.villageheart.needs_tool.<id>` key.
6. The r1 notes about `CANT_REACH_WALK_TARGET_SINCE` (not erased in `DepositTrip.start`) and the PROGRESS test counts still apply. Both are minor.
