## Test-infrastructure risks the builder flagged

**`sweepStrayMarkers` is safe today.** Reasons:

- The run log shows GameTest batches running one after another (one progress step per batch). Each building test that calls `begin` or
  `sweepStrayMarkers` has its own `buildings_<name>` environment, so it is alone in its batch (`batch 0 (1 tests)` for all 13).
- No test runs at the same time as a sweep. Earlier batches are already finished, and later batches place their own markers after it.
- The only multi-test batches (`minecraft:default`, 12 tests, and `markers`, 17 tests) never sweep. That includes `roomCellsGroups`, the one building test in the default environment, which places no markers.
- A non-building test cannot lose markers. The sweep reach (160) covers the adoption reach (128).
- It becomes unsafe only if a future test that calls `begin` shares an environment with another test (see note 3).

## Non-blocking notes

1. **`outsideClaimAndNoClaim` reads `messages.get(0)` without a guard** (`BuildingGameTests.java` lines 205, 218, 239).
   - If no message arrives, the `IndexOutOfBoundsException` is not an assertion. It escapes `GameTestSequence.executeWithoutFail` and crashes the whole GameTest server ("Game test server crashed"), as seen under mutation 9.
   - The run still fails, so this is not a vacuous test. But it hides every result after it.
   - Fix: `h.assertTrue(!messages.isEmpty(), ...)` first. The same applies to `rightClickReport` (it guards with `size() >= 3` once), `lineBody(...get(1))` and `reasons(...).get(0)` inside waits.
2. **The filter quirk is a trap.** A filter that is not an exact id passes with 0 tests.
   - Suggest that the runner, or a wrapper script, fail when a filter is set and 0 tests ran.
   - Fabric's behaviour, not M5's, but the M5 docs now teach people to use the filter.
3. **The sweep depends on "one building test per environment".**
   - Suggest an assertion in `begin`, or a sentence in TESTING.md, saying a test that sweeps must never share an environment. Otherwise a future shared environment could silently delete a concurrent test's markers.
4. **Known leniencies,** all documented in DESIGN or the plan:
   - After a restart, the Hunting Ground home-room exclusion is lenient until the House or Farmhouse is re-scanned (it self-heals within one cycle).
   - Never-registered out-of-claim plaques stay red after a release.
   - Markers in chunks loaded after the claim are adopted only on a right-click.
5. **The L4 test does not assert the client chat.** It checks the server verdict and relies on the screenshot for the chat lines. Acceptable for a screenshot criterion.
6. **The Layer-4 network-synchronizer flake hit run 1 here as well.** It is being fixed separately.
