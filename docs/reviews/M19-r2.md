## Fix list

1. **Server hang: `SmithCrafts.refund` never ends when a committed id is not a registered item. Blocking.**
   - **Where:** `src/main/java/dev/villageheart/worker/smith/SmithCrafts.java`, `refund`, the `while (remaining > 0)` loop.
   - **What's wrong:**
     - `BuiltInRegistries.ITEM.getValue` returns `AIR` for an unknown id.
     - `new ItemStack(AIR, n)` is empty, and `getCount()` is 0 for an empty stack (1.21.11 bytecode: `isEmpty() ? 0 : count`).
     - So `remaining -= stack.getCount()` never decreases `remaining`.
   - **Why it is reachable:**
     - The save codec (`VillageCodecs.SAVED_SMITH`, `ITEM_COUNT`) accepts any string as an item id.
     - A save with a removed or modded item, or an edited one, is exactly the "bad saved craft" that round-1 item 6 asked to refund.
     - Before this round, `refund` ran only on a cancel, an orphan or a claim release. Now `SmithySystem` calls `retryPending` every 100 ticks, so the hang comes on its own soon after load.
   - **Evidence:** a throwaway GameTest, not committed.
     - It seeds `withSmithCraft(furnace, new SmithCraft(craft, mine, true))` with committed `minecraft:no_such_item` x3 and `minecraft:stick` x2, then waits for the record to go.
     - With the unknown id: the log stops after `PROBE seeded…`, and `maxTicks = 600` (30 s) never fires. `timeout 420` killed the run (exit 124).
     - Control, the same test with `minecraft:iron_ingot`: `PROBE record gone` one second later, and the test passes.
   - **Same loop elsewhere:** `SelfCrafts.refund` (`worker/gear/SelfCrafts.java`, M19a) has the identical loop. Fix it the same way.
   - **Also check:** a malformed id, such as one with a capital letter or a space, makes `Identifier.parse` throw. I did not test this. Use `Identifier.tryParse` and treat it as unknown.
   - **Expected:**
     - An id that does not resolve to a real item is never looped on. Log a warning and drop that entry: it is not a real item, so nothing is lost. The rest of the craft is refunded and the record goes.
     - Optionally the codec flags such an entry when it loads.
     - Add a GameTest like the probe above that fails today (hang, or record still saved) and passes after the fix, and the same for a self-craft.

2. **Golem materials can be lost when a build is refunded with no Storage and the Smithy chunk unloaded. Should fix, not blocking.**
   - **Where:** `worker/smith/GolemBuilds.refund`.
   - **What's wrong:**
     - The record is removed before it is known that the 36 ingots and the pumpkin can be placed.
     - `give` falls back to `LOG.warn("… left behind")`, so the materials are gone.
     - `refundAll` on a claim release can hit this.
     - This code dates from round 1 and is not part of the round-1 fixes.
   - **Expected:** as `SmithCrafts.refund` does, keep the build record (or a pending refund) until everything has been placed.

3. **`SmithJob.withdraw`: the leftover of a deposit-back is not checked. Minor, round-1 code.**
   - **What's wrong:** `if (!rest.isEmpty()) Stockpiles.deposit(level, at, rest);` ignores what `deposit` could not store.
   - **Expected:** `keepOrDrop(v, rest)` after the deposit.
   - This is only reachable if the Storage that was just withdrawn from has filled up in the same tick, so it is very unlikely.
